Title: pkgbase: Extract pkgbase variables into separate file

Description:
This PR is the first step in modularizing the pkgbase build system.
It extracts all pkgbase-related configuration variables from Makefile.inc1
into a dedicated file tools/pkgbase/build/vars.mk.

This change:
- Improves maintainability by separating configuration from logic
- Makes it easier to find and modify pkgbase settings
- Prepares the foundation for further modularization (Part 2 & 3)
- Reduces Makefile.inc1 by ~20 lines

No functional changes - the build behaves identically.

.export PKG_NAME_PREFIX
.export PKG_MAINTAINER
.export PKG_WWW

.if !defined(PKG_TIMESTAMP)

.endif

7. DISCUSSION POINTS FOR REVIEW
================================================================================

Potential Questions:

Q: Why not keep everything in Makefile.inc1?
A: Monolithic files are harder to maintain. This separation makes it clear
   which variables belong to pkgbase and allows easier modification.

Q: Does this affect existing users?
A: No - the include happens at the same point in processing, and all
   variables have ?= assignments, preserving any user overrides.

Q: Why tools/pkgbase/build/ not just tools/pkgbase/?
A: Anticipating future structure: build/ will contain build system files,
   while root might contain scripts like metalog_reader.lua.

Q: Should we move more variables?
A: Not in this PR. Additional variables (PKG_LEVEL, PKG_CTHREADS, etc.)
   will be evaluated in Part 2 and Part 3.

8. BACKWARD COMPATIBILITY
================================================================================

This change maintains full backward compatibility:

1. Variable definitions use ?= (lazy assignment), so user overrides
   in /etc/src.conf or /etc/make.conf are preserved.

2. The include happens at the exact same location in Makefile.inc1,
   maintaining processing order.

3. All variables have the same default values as before.

4. No changes to public interfaces or user-visible behavior.
